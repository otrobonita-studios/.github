# Security

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability, exposed credential,
or supply-chain concern in an Otrobonita repository.

Use GitHub's private vulnerability reporting on the affected repository when
it is enabled, or contact the organization through the verified channels on
[otrobonita.com](https://www.otrobonita.com/).

Include the repository, revision, reproduction steps, potential impact, and
any safe evidence you can share. Do not include live secrets or personal data.

## Public vs private work

Public repositories are intended to be read. They must not contain credentials,
private keys, customer data, or internal-only URLs. If you find any of those
in a public tree, report them as a vulnerability, not as a drive-by README
edit.
