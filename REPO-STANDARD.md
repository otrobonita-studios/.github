# Public repository standard

Otrobonita AI Labs. Applies to **public** repositories under
`otrobonita-studios`. Private working copies may be messier; they must be
finished as repositories before they are made public.

## Required on every public repo

| Field | Rule |
|---|---|
| About | One sentence a stranger can understand. Not empty. |
| Homepage | Live URL if there is one. |
| README | Purpose, who it is for, how to run or read, status (experiment vs product), how it relates to sibling repos. |
| License | A file GitHub can detect. No `NOASSERTION` from a custom paraphrase. |
| Topics | A few accurate topics. |

## Forbidden on public repos

- Stock create-next-app / CRA / Vite getting-started READMEs.
- Empty About boxes on anything linked from the org profile.
- Leftover brand names from another company unless the first sentence says
  this is an app kit or historical archive.
- Public forks whose name implies a third-party product you do not own,
  without a “relationship to upstream” section and a license.
- Pointers to CLIs, MCP servers, or binaries that do not live in the repo and
  are not linked.

## Public vs private

Publish when you want the work judged. Keep private while it is a scaffold, a
dump, or an internal experiment. Org hygiene (this file, `llms.txt`, the
profile README) changes when the public set changes. Engineering practice
changes in [playbook](https://github.com/otrobonita-studios/playbook).
